## 구조 (제안)
- Python 서버 하나(Hugging Face Spaces, Docker, CPU)가 `POST /analyze`에서 OCR → 숫자 형식 개인정보 지우기 → 파싱 → 검증을 한다.
- Supabase `analyze` Edge Function은 요청을 전달만 한다.
- 서버 주소는 공개라서 Edge Function이 보내는 공유 비밀 헤더와 파일 크기 제한을 둔다. 키는 Space secret으로만 둔다.
- 이미지와 추출 텍스트는 저장하거나 로그에 남기지 않는다.

## 배준서: OCR 서버와 파싱
1. **OCR 서버.** PaddleOCR PP-OCRv5 korean(CPU)로 이미지 1장을 받아 텍스트를 돌려주는 Python 서버를 만든다. Hugging Face Spaces CPU Basic을 먼저 시도하고, PaddleOCR 모델을 이미지에 미리 포함해 첫 요청 지연을 줄인다. 배포 주소를 백엔드(조계진, 유예찬)에 전달한다.
2. **파싱.** OCR 텍스트를 "analyze 출력 데이터" 형식으로 바꾼다. 방식(규칙 또는 Claude 텍스트 호출)과 이유를 `모델-배준서.md`에 한 줄로 적는다.
3. **개인정보 처리.** 외부 AI를 부르기 전에 주민번호, 전화번호, 계좌번호처럼 형식이 일정한 숫자를 지운다.
4. **검증.** 파싱 결과가 값 규칙을 지키는지 코드로 검사하고, 어긋난 값은 비운다.
5. **읽기 실패.** 제도마다 핵심 항목(`deadline`, `periodText`, `minAge`, `maxAge`, `docs`, `office`, `applyMethod`)이 모두 비면 `{"code": "UNREADABLE"}`와 HTTP 4xx(예: 422)를 돌려준다.
6. **평가 결과 반영.** Claude가 알려 준 틀린 곳을 고친다.
7. **포스터형 확인.** `1.jpg`, `2.jpg`처럼 OCR 글자가 깨진 이미지에서 틀린 값이 채워지지 않게 한다. 틀린 값보다 빈 값이 낫다.
8. **백엔드 연동.** `analyze` Edge Function이 서버를 부르는 방식(주소, 인증, 제한 시간 60초)을 백엔드와 정한다.
