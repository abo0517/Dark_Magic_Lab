## 구조 (제안)
- Python 서버 하나(Hugging Face Spaces, Docker, CPU)가 `POST /analyze`에서 OCR → 숫자 형식 개인정보 지우기(`model/server`) → 파싱과 검증(`model/server/parse.py`, 준서) 순서로 처리한다.
- Supabase `analyze` Edge Function은 요청을 전달만 한다.
- 서버 주소는 공개라서 Edge Function이 보내는 공유 비밀 헤더와 파일 크기 제한을 둔다. 키는 Space secret으로만 둔다.
- 이미지와 추출 텍스트는 저장하거나 로그에 남기지 않는다.

## 안병욱: OCR 서버와 정책 추출
1. **OCR 서버 코드(`model/server/`).** 로컬 세션(`AI 해커톤 스인개`)에 맡긴다. PaddleOCR PP-OCRv5 korean(CPU)로 이미지를 읽고, 숫자 형식 개인정보(주민번호, 휴대전화번호)를 지운 뒤, 준서가 만드는 `parse.py`를 불러 `analyze` 응답을 돌려주는 Python 서버다. 파일 크기와 형식 검사, 공유 비밀 헤더 검사, 읽기 실패(`UNREADABLE`) 응답도 이 서버가 처리한다.
2. **서버 배포.** Hugging Face Spaces(Docker, CPU Basic) 계정에서 Space를 만들고 `model/server/`를 올려 배포한다(사람이 직접). 배포 주소와 공유 비밀 값을 백엔드(조계진, 유예찬)에 전달한다.
3. **정책 조건 추출 프롬프트(`sync-policies`용).** 로컬 세션에 맡겨 `model/policy_extract.py`로 만든다. 샘플 결과를 확인하고, 정책 테이블 열과의 대응을 백엔드에 전달한다.
4. **백엔드 연동.** `analyze` Edge Function이 서버를 부르는 방식(주소, 인증, 제한 시간 60초)을 백엔드와 정한다.
5. **기획서 AI 부분.** 처리 방식, 오류 방지 원칙(지어내지 않기, `UNREADABLE`), 개인정보 처리를 쓴다.
6. **`모델-안병욱.md` 갱신, 발표자료의 모델 설명.**

## 배준서: 파싱과 검증
1. **파싱(`model/server/parse.py`).** `parse(text)`가 OCR 텍스트를 받아 "analyze 출력 데이터" 형식(`{easySummary, programs[]}`)을 돌려주도록 만든다. 서버 골격은 안병욱 쪽에서 만든다. 방식(규칙 또는 Claude 텍스트 호출)과 이유를 `모델-배준서.md`에 한 줄로 적는다. Claude를 쓰면 키는 서버 환경변수로 받는다.
2. **검증.** 파싱 결과가 값 규칙을 지키는지 코드로 검사하고, 어긋난 값은 비운다.
3. **평가 결과 반영.** Claude가 알려 준 틀린 곳을 고친다.
4. **포스터형 확인.** `1.jpg`, `2.jpg`처럼 OCR 글자가 깨진 이미지에서 틀린 값이 채워지지 않게 한다. 틀린 값보다 빈 값이 낫다.
