- 응답 형식은 `개발계획.md`의 "analyze 출력 데이터"가 기준이다.
- 마감은 16:00이고 이후 코드 변경은 무효다. 코드 동결은 15:45.
- 정답 검수와 평가는 팀원이 하지 않는다. 결과가 나오면 Claude(클라우드 세션)가 결과를 이미지와 직접 대조해 핵심 4개(기한, 나이, 서류, 접수처)와 지어낸 값을 점검하고 틀린 곳을 알려 준다. `model/answer.json`은 AI가 만든 참고 자료다.

## 구조
- Python 서버 하나(팀 컴퓨터에서 직접 실행, Docker 사용 안 함)가 `POST /analyze`에서 이미지나 PDF를 Claude(`claude-sonnet-5-5`)에 바로 보내 `{easySummary, programs[]}`를 받아 돌려준다. OCR 모델은 쓰지 않는다(`model/server/`).
- Supabase `analyze` Edge Function은 요청을 전달만 한다.
- 서버 주소는 공개라서 Edge Function이 보내는 공유 비밀 헤더와 파일 크기 제한을 둔다. 키(`SHARED_SECRET`, `ANTHROPIC_API_KEY`)는 서버 환경변수나 `.env`로만 둔다.
- 이미지는 Claude API(외부)로 전송된다. 이미지와 응답 내용은 저장하거나 로그에 남기지 않는다.

## 안병욱: 서버 운영과 정책 추출
1. **개인정보 공지(미구현).** 이미지는 외부(Claude API)로 전송되는데, 개인정보가 포함된 파일일 때만 이 사실을 공지한다(요구).
   - 문제: OCR을 뺐기 때문에 개인정보가 있는지 보내기 전에 서버가 알 수 없다. 개인정보가 있는지 Claude에게 판별시키면 그때 이미 전송된 뒤다.
   - 후보: (가) 응답에 개인정보 포함 여부 표시(예: `hasPersonalInfo`)를 넣고 프론트가 공지(전송 후라는 한계), (나) 업로드 전에 사용자가 개인정보 포함 여부를 확인, (다) 로컬 판별용 OCR을 다시 도입. 방식은 팀이 정한다.
   - 지금은 프롬프트로 개인 번호를 결과에 넣지 않게 하고, 응답의 주민번호와 휴대전화번호 형식을 `[삭제]`로 바꾸는 것까지만 한다(`model/server/mask.py`).
   - 프론트 요청: 지금은 업로드 때마다 "저장하지 않아요" 고지가 나온다. 정해지면 표시 조건을 바꿔야 한다(프론트 담당).
2. **서버 운영과 공개 주소.** 백엔드 일이 많아서 Claude 호출은 모델 팀 서버(`model/server/`)가 맡는다. 팀 컴퓨터에서 서버를 실행하고, 백엔드(조계진, 유예찬)의 `analyze` Edge Function은 이 서버로 요청을 전달만 하게 한다.
   - 공개 주소: 이 컴퓨터에 설치된 `cloudflared`의 임시 터널(`cloudflared tunnel --url http://localhost:7860`)로 만들 수 있다. 계정 없이 주소가 나오지만 다시 실행하면 주소가 바뀌므로 시연 동안 켜 두고, 바뀌면 백엔드에 다시 알려야 한다. 서버가 켜져 있어야 하고 컴퓨터가 절전에 들어가면 안 된다.
   - 백엔드에 전달: 서버 주소, `SHARED_SECRET` 값, 요청 형식(`POST /analyze`, 필드 `file`, 헤더 `X-Shared-Secret`), 오류 코드.
   - 주의: 공개 주소는 유료 Claude 호출로 이어지므로 `SHARED_SECRET`은 추측하기 어려운 긴 값으로 정하고 저장소와 채팅에 남기지 않는다.
3. **정책 조건 추출(`sync-policies`용).** `model/policy_extract.py`(모델 `claude-sonnet-5-5`)로 샘플 결과를 확인하고 정책 테이블 열과의 대응을 백엔드에 전달한다. 정책 API 호출과 `DATA_GO_KR_KEY`는 백엔드 몫이라, 백엔드의 샘플 상세 5건을 읽어 추출만 하도록 고친다.
4. **백엔드 연동.** `analyze` Edge Function이 서버를 부르는 방식(주소, 인증, 제한 시간 60초)과 오류 코드(`UNREADABLE`, `TOO_LARGE`, `UNSUPPORTED`, `UNAUTHORIZED`, `UPSTREAM_ERROR`, `TIMEOUT`)를 백엔드와 정한다.
5. **기획서 AI 부분.** 처리 방식, 오류 방지 원칙(지어내지 않기, `UNREADABLE`), 개인정보 처리를 쓴다.
6. **`모델-안병욱.md` 갱신, 발표자료의 모델 설명.**

## 배준서: 파싱과 검증
1. **파싱(`model/server/parse.py`).** 서버가 OCR 없이 Claude에 이미지를 바로 보내게 되어 지금은 서버에 연결하지 않았다. 이 파서를 쓸지(예: Claude 응답 검증용) 버릴지 안병욱과 정한다.
2. **검증.** 파싱 결과가 값 규칙을 지키는지 코드로 검사하고, 어긋난 값은 비운다.
3. **평가 결과 반영.** Claude가 알려 준 틀린 곳을 고친다.
4. **포스터형 확인.** `1.jpg`, `2.jpg`처럼 글자가 적은 포스터에서 틀린 값이 채워지지 않게 한다. 틀린 값보다 빈 값이 낫다.
