# 모델 - 안병욱

## 코드
- `test_vision.py`: 폴더의 안내문 이미지(jpg, jpeg, png, webp)를 하나씩 Claude Vision(`claude-opus-5-5`)에 보내 제도별 항목을 JSON으로 받는다. 결과는 `claudeVision_test.json`에 저장한다.
  - 실행: `python model/ClaudeAPI/test_vision.py model/data`
  - 키: 저장소 루트 `.env`의 `ANTHROPIC_API_KEY`. 의존: `pip install anthropic`
  - 출력: `{"easySummary", "programs":[제도 1건 19개 키]}`. 키는 `개발계획.md`의 "안내문에서 뽑을 항목" 표를 따른다.
  - 오류: 폴더 없음, 키 없음, 이미지 없음, 5MB 초과, 거절, 응답 잘림, API 오류. 파일 하나가 실패해도 다음 파일을 계속 처리한다.
- `model/server/`: OCR 서버(FastAPI). 이미지와 PDF를 받아 PP-OCRv5로 읽고 → 주민번호·휴대전화 숫자를 `[삭제]`로 바꾸고(`mask.py`) → `parse.py`(배준서)로 정리해 `{easySummary, programs}`를 돌려준다. `GET /health`, `POST /ocr`, `POST /analyze`. 팀 컴퓨터에서 직접 실행한다(Docker 사용 안 함). 실행 방법은 `model/server/README.md`.
- `model/policy_extract.py`: 정책 상세 텍스트에서 19개 키를 뽑는 프롬프트와 스크립트(모델 `claude-sonnet-5-5`).
- `model/model_compare.py`: Opus, Sonnet, Haiku를 같은 입력으로 비교한다. 결과는 `model/model_compare_result.json`.
- `model/data/`: 샘플 안내문 이미지.
- `model/answer.json`: 샘플 11장의 정답 데이터(AI가 이미지를 읽어 만든 참고 자료).

## 진행 상황
- Node 스크립트를 Python으로 바꿨고, 11장을 모두 돌려 JSON 파싱과 키 19개 존재를 확인했다.
- 정답 데이터를 기준으로 20개 제도를 비교했다. 일치 수는 Claude Vision이 기한 18, 나이 20, 서류 19, OCR 결과(`model/ocr/ocr-fields.json`)가 기한 19, 나이 17, 서류 18이다. 기한 불일치는 "상시"를 `always`로 보는 규칙이 이전 프롬프트에 없어서 생긴 것이다.
- 샘플 11장은 OCR 방식으로 가기로 정했다. 포스터형(`1.jpg`, `2.jpg`)은 OCR 글자가 많이 깨졌다.
- 모델 3종 비교(66번 호출, 실패 0, 스키마 위반 0): 호출당 평균 시간은 Opus 약 15초, Sonnet 약 8.6초, Haiku 약 11초. 정책 858건 추정 비용은 Opus $39, Sonnet $16, Haiku $1.3. 정책 추출은 Sonnet으로 정했다. 값의 품질은 아직 이미지와 대조하지 않았다.
- OCR 서버를 로컬에서 실행해 확인했다: 헤더 없음 401, 11MB 413, 지원 안 하는 형식 415, 깨진 파일 422, 이미지와 PDF 처리. 메모리는 약 0.5GB. 기본 모델(PP-OCRv5 server 검출)은 CPU에서 느리다(`1.jpg` 16초, `2.jpg` 39초, 2360x3328 이미지는 5분 초과). 요청 60초 제한을 넘길 수 있어 OCR 속도 개선은 준서 쪽에서 정한다. `enable_mkldnn=False`가 없으면 이 컴퓨터에서 oneDNN 오류로 모든 요청이 실패한다.
- 서버 오류 코드 규칙: 준서의 `parse()`가 `UnreadableError`를 던지면 서버가 422 `UNREADABLE`로 바꾼다.
- 정리한 것: 준서의 `parse.py`가 제 자리표시 파일에 덮여 사라져 있어서 복원했다. `model/ClaudeAPI/test_vision.py`의 `.env` 경로가 한 단계 어긋나 있어서 고쳤다.
- 남은 문제
  - `test_vision.py` 프롬프트에 "상시 접수는 `always`", "`gu`는 구 이름만", "서류 중복과 안내 문구 제외" 규칙을 반영하지 않았다(OCR 방식으로 가면 Plan B용).
  - 거절(`refusal`) 응답은 재현하지 못했다.
- 구현하지 못한 것
  - `policy_extract.py`는 정책 API 호출까지 하지만 API 호출과 `DATA_GO_KR_KEY`는 백엔드 몫이다. 백엔드의 샘플 정책 상세 5건(중앙부처 3, 서울 지자체 2)을 받아 추출만 하도록 바꿔야 하고, 아직 실행하지 못했다.
  - 서버를 외부에서 부르려면 공개 주소(터널 등)가 필요하다. 아직 정하지 않았다.
  - PDF는 앞 5쪽만 읽고, 큰 PDF는 느리다.
- 백엔드에 요청: 정책 상세 샘플 5건, `analyze`가 서버를 부르는 방식(주소, `X-Shared-Secret` 헤더, 제한 시간 60초), 오류 코드 합의(`UNREADABLE` 외 `BLURRY`, `CROPPED`는 서버에서 아직 구분하지 않는다).
