# 모델 - 안병욱

## 코드
- `model/server/`: 모델 서버(FastAPI). 이미지나 PDF를 받아 Claude(`claude-sonnet-5-5`)에 그대로 보내 `{easySummary, programs[19개 키]}`를 구조화 출력으로 받아 돌려준다. OCR 모델은 쓰지 않는다. 응답의 주민번호·휴대전화 형식은 `[삭제]`로 바꾸고(`mask.py`), 값 규칙에 어긋난 값은 비운다(`validate.py`). 응답에는 개인정보 포함 여부 `hasPersonalInfo`가 들어간다. `GET /health`, `POST /analyze`. 팀 컴퓨터에서 직접 실행한다(Docker 사용 안 함). 실행 방법과 오류 코드는 `model/server/README.md`.
- `model/policy_extract.py`: 정책 상세 텍스트에서 같은 19개 키를 뽑는 프롬프트와 스크립트(모델 `claude-sonnet-5-5`). 백엔드가 준 샘플 JSON을 읽는다(정책 API 호출은 백엔드 몫). 서버의 프롬프트 규칙과 스키마도 여기서 가져온다.
- `model/eval_server.py`: 샘플 11장을 서버와 같은 경로로 분석해 `model/answer.json`과 비교한다(호출 11번).
- `model/data/`: 샘플 안내문 이미지.
- 근거로 남긴 결과 파일: `model/answer.json`(샘플 정답, AI가 이미지를 읽어 만든 참고 자료), `model/ClaudeAPI/claudeVision_test.json`(Claude Vision 결과), `model/ocr/ocr-results.md`와 `ocr-fields.json`(OCR 결과), `model/model_compare_result.json`(모델 3종 비교).

## 진행 상황
- 정답 데이터를 기준으로 20개 제도를 비교했다. 일치 수는 Claude Vision이 기한 18, 나이 20, 서류 19, OCR 결과가 기한 19, 나이 17, 서류 18이다. 기한 불일치는 "상시"를 `always`로 보는 규칙이 이전 프롬프트에 없어서 생긴 것이다.
- OCR 모델(PaddleOCR)은 이 컴퓨터 CPU에서 느려서(2360x3328 이미지는 5분 초과) 쓰지 않고, 이미지를 Claude에 직접 보내기로 했다.
- 서버를 로컬에서 실행해 확인했다: 헤더 없음 401, 6MB 이미지와 11MB PDF 413, txt 415, 깨진 이미지 422, PDF 200. 터널 경유 호출도 확인했다. 서버는 `127.0.0.1`로 열고 터널로 공개한다.
- 샘플 11장 평가(`eval_server.py`): 프롬프트에 "종류별 분리", "서류 한 개당 한 항목", "상대 기간은 relative"를 넣은 뒤 11장 중 9장에서 기한, 나이, 서류, 접수처가 모두 일치했다(기준 8장). 항목별로 기한 20/20, 나이 20/20, 서류 19/20, 접수처 20/20(짝지어진 제도 20개 기준). 불일치는 군소음 안내문의 서류 1건과 근로장려금(정답은 1건, 모델은 2건)이다. 정답이 AI가 만든 것이라 이미지를 직접 봐야 확정된다. `hasPersonalInfo`는 11장 모두 false였다.
- 큰 오독은 아직 정답과 대조하지 않았다. 작은 글자 오독(군소음의 "율문길"을 "울문길"로 읽는 식)이 있었다.
- 정리한 것: OCR 코드, OCR 중복 파일, `ClaudeAPI/test_vision.py`, `model_compare.py`, `__pycache__`를 지웠다. 준서의 `model/server/parse.py`는 OCR 텍스트용이라 서버에 연결하지 않았고 파일은 그대로 두었다.

## 구현하지 못한 것
- 개인정보 공지 표시: 서버는 `hasPersonalInfo`를 주지만, 프론트가 언제 공지를 띄울지는 팀이 정해야 한다(보내기 전에 개인정보 포함 여부를 알 수 없다). `남은구현목록.md` B와 C.
- `policy_extract.py` 실제 실행: 백엔드의 샘플 정책 상세 5건이 필요하다(안내문 텍스트 1건으로 스키마 호출만 확인했다). `policies` 열을 채우는 방식은 백엔드와 정해야 한다.
- 백엔드 `analyze` Edge Function이 없어서 화면까지 이어지는 전체 흐름은 시험하지 못했다.
- 요건형 안내문(근로장려금처럼 기한, 서류, 접수처가 없는 것)을 `UNREADABLE`로 볼지 정해야 한다.
- `BLURRY`, `CROPPED` 오류 코드는 구분하지 않는다. 거절(`refusal`) 응답은 재현하지 못했다.

## 백엔드에 요청
- 정책 상세 샘플 5건.
- `analyze`가 서버를 부르는 방식: 주소, `X-Shared-Secret` 헤더, 제한 시간 60초.
- 오류 코드 합의: `UNREADABLE`, `TOO_LARGE`, `UNSUPPORTED`, `UNAUTHORIZED`, `UPSTREAM_ERROR`, `TIMEOUT`.
