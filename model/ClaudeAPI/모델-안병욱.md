# 모델 - 안병욱

## 코드
- `model/server/`: 모델 서버(FastAPI). 이미지나 PDF를 받아 Claude(`claude-sonnet-5-5`)에 그대로 보내 `{easySummary, programs[19개 키]}`를 구조화 출력으로 받아 돌려준다. OCR 모델은 쓰지 않는다. 응답의 주민번호·휴대전화 형식은 `[삭제]`로 바꾼다(`mask.py`). `GET /health`, `POST /analyze`. 팀 컴퓨터에서 직접 실행한다(Docker 사용 안 함). 실행 방법과 오류 코드는 `model/server/README.md`.
- `model/policy_extract.py`: 정책 상세 텍스트에서 같은 19개 키를 뽑는 프롬프트와 스크립트(모델 `claude-sonnet-5-5`). 서버의 프롬프트 규칙과 스키마도 여기서 가져온다.
- `model/data/`: 샘플 안내문 이미지.
- 근거로 남긴 결과 파일: `model/answer.json`(샘플 정답, AI가 이미지를 읽어 만든 참고 자료), `model/ClaudeAPI/claudeVision_test.json`(Claude Vision 결과), `model/ocr/ocr-results.md`와 `ocr-fields.json`(OCR 결과), `model/model_compare_result.json`(모델 3종 비교).

## 진행 상황
- 정답 데이터를 기준으로 20개 제도를 비교했다. 일치 수는 Claude Vision이 기한 18, 나이 20, 서류 19, OCR 결과가 기한 19, 나이 17, 서류 18이다. 기한 불일치는 "상시"를 `always`로 보는 규칙이 이전 프롬프트에 없어서 생긴 것이다.
- OCR 모델(PaddleOCR)은 이 컴퓨터 CPU에서 느려서(2360x3328 이미지는 5분 초과) 쓰지 않고, 이미지를 Claude에 직접 보내기로 했다.
- 서버를 로컬에서 실행해 확인했다(`model/data` 11장): 10장 200(4~12초, 평균 8초, 복지 서비스.jpg는 제도 7건), 근로장려금 체크리스트 1장은 핵심 7개 키가 모두 비어 422 `UNREADABLE`. PDF 200(15초). 헤더 없음 401, 6MB 이미지와 11MB PDF 413, txt 415, 깨진 이미지 422.
- 큰 오독은 아직 정답과 대조하지 않았다. 군소음 안내문에서 "율문길"을 "울문길"로 읽는 식의 작은 글자 오독이 있었다.
- 정리한 것: OCR 코드(`ocr.py`), OCR 중복 파일(`model/ocr/`의 복사본 3개), `ClaudeAPI/test_vision.py`, `model_compare.py`를 지웠다. 준서의 `model/server/parse.py`는 OCR 텍스트용이라 서버에 연결하지 않았고 파일은 그대로 두었다.

## 구현하지 못한 것
- 개인정보가 포함된 파일일 때만 외부 전송을 공지하는 기능(보내기 전에 개인정보 포함 여부를 알 방법이 없다). 자세한 내용은 `model/해야할일.md`.
- `policy_extract.py`는 정책 API 호출까지 한다. API 호출과 `DATA_GO_KR_KEY`는 백엔드 몫이라, 백엔드의 샘플 상세 5건(중앙부처 3, 서울 지자체 2)을 읽어 추출만 하도록 바꿔야 하고 아직 실행하지 못했다.
- 서버를 외부에서 부르려면 공개 주소(터널 등)가 필요하다. 아직 정하지 않았다.
- 근로장려금 같은 요건형 안내문(기한, 서류, 접수처 없음)을 `UNREADABLE`로 볼지 정해야 한다.
- `BLURRY`, `CROPPED` 오류 코드는 구분하지 않는다. 거절(`refusal`) 응답은 재현하지 못했다.

## 백엔드에 요청
- 정책 상세 샘플 5건.
- `analyze`가 서버를 부르는 방식: 주소, `X-Shared-Secret` 헤더, 제한 시간 60초.
- 오류 코드 합의: `UNREADABLE`, `TOO_LARGE`, `UNSUPPORTED`, `UNAUTHORIZED`, `UPSTREAM_ERROR`, `TIMEOUT`.
