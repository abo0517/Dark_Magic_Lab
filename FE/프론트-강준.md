## 백엔드·모델에 요청 (프론트가 이렇게 쓰고 있으니 다르면 알려주세요)

백엔드 (조계진, 유예찬)
1. Supabase 프로젝트 URL과 anon key를 팀 채널로 전달 (`FE/.env.local`에 넣음. 저장소에 올리지 않음)
2. `policies` 테이블 읽기 허용(RLS select). 프론트가 기대하는 열: `name`, `summary`, `eligibility`, `min_age`, `max_age`(없으면 null), `source`('central'|'local'), `ctpv`, `sgg`, `deadline`(YYYY-MM-DD, 없으면 null), `docs`(text 배열), `office`, `detail_link`
3. 프론트 조회: `GET /rest/v1/policies?select=*&limit=500&and=(나이 조건 or, source.eq.central 또는 ctpv.eq.서울특별시)`. 열 이름이 다르면 알려주세요. 지자체 `sgg`가 "마포구"처럼 구 이름 그대로인지 확인 필요(구 비교에 씀)
4. `analyze` Edge Function: 프론트는 `POST` + `multipart/form-data`(필드명 `file`) + `Authorization: Bearer <anon key>`로 호출하도록 만들어 둠. 다르면 알려주세요. CORS 허용과 파일 크기 제한도 필요

모델 (안병욱, 배준서)
5. `analyze` 응답을 아래 형식으로 확정 (프론트 결과 화면이 이 형식으로 만들어져 있음. 값이 없으면 빈 문자열/빈 배열)
   `{ kind, easySummary, source, todos[], facts[], programs[] }`
   - `kind`: 안내문 종류(예: 기초연금 안내문)
   - `todos[]`: `{ text, deadline }` 해야 할 일과 기한(YYYY-MM-DD, 없으면 빈 문자열)
   - `facts[]`: `{ label('신청 기한'|'지원 금액'|'제출처'), value, evidence(원문 그대로 발췌), uncertain(잘 안 읽혔으면 true) }`
   - `programs[]`: `name, summary, minAge, maxAge, gu, deadline, office, docs[]`
6. 읽기 실패 응답 제안: HTTP 422 + `{ "code": "UNREADABLE" | "BLURRY" | "CROPPED" }`, 서버·네트워크 장애는 5xx. 프론트는 `code`로 안내 문구를 나눔 (합의 필요)
7. 모델 출력(19개 키)은 프론트가 변환하므로 `analyze`는 모델 출력 그대로 돌려줘도 됨. 스크립트는 이미지(jpg/png/webp)만 처리하고 PDF는 미지원이라 PDF 지원 여부 확인 필요
8. 프론트는 이미지를 긴 변 1568px JPEG로 줄여 보냄(모델 스크립트의 5MB 제한 안쪽). PDF는 줄이지 못하므로 서버 크기 제한을 알려주세요
9. AI 공급자가 미확정(`개발계획.md`는 Claude Vision, `CODEX.md`는 OpenAI). 프론트는 응답 형식만 맞으면 영향 없음

- 안내문 분석(`analyzeRemote`): 백엔드 Edge Function `analyze`(`multipart`의 `file`, `apikey` 헤더, 오류는 `{code}` JSON)와 형식 일치 확인. 응답의 `hasPersonalInfo`가 true이면 결과 화면에 개인정보 안내를 표시
- 서버 오류 코드 안내: `UNREADABLE`, `TOO_LARGE`, `UNSUPPORTED`, `UPSTREAM_ERROR`, `TIMEOUT`. 그 외(`UNAUTHORIZED` 등)는 일반 오류 문구
- 소셜 로그인: 구글·카카오는 백엔드가 Supabase에 연결. 로그인 실패 시 Supabase가 돌려주는 오류 문구를 로그인 화면에 표시(`oauthError`). 네이버는 "준비 중"

- 개발 서버 전용: 주소 끝에 `?demo`를 붙이면 구글 로그인과 프로필 저장을 건너뜀(배포본에는 없음)
